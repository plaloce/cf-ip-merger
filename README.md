# CF 优选 IP 合集工具

一个无需安装、全程本地运行的 Windows 桌面工具：集中管理多个在线 TXT 来源，按 IPv4 / IPv6 筛选并合并为 `优选合集.txt`。

当前版本：**v1.1.1**  
支持系统：Windows 10 / 11（64 位）

## 主要功能

- 管理多个 URL 来源，支持备注、启停和排序
- 来源修改后立即自动写入 `URL.txt`，无需手动保存
- IPv4 / IPv6 类型筛选，只导出勾选类型
- 可选整行精确去重（默认开启）
- 可选 GitHub 加速，通过 `gh-proxy.org` 下载 GitHub 来源
- 合并期间可随时停止，不写入或覆盖旧结果
- 输出选项自动保存至 `程序配置.json`，下次启动恢复

## 快速开始

1. 将 zip 完整解压到普通可写目录，不要直接在压缩包预览中运行。
2. 确认 `CF优选IP合并工具.exe`、`URL.txt`、`程序配置.json` 在同一目录。
3. 双击 exe，检查来源列表和“输出筛选”。
4. 点击“开始合并”。
5. 完成后，同目录生成 `优选合集.txt`。

默认设置为：整行精确去重开启、IPv4 开启、IPv6 关闭、GitHub 加速关闭。

> 不要只把 exe 放进 `C:\Program Files` 等需要管理员权限的目录。程序需要读写同目录的配置文件和结果文件。

合并期间，按钮会变成红色“停止合并”。点击后任务停止并恢复为“开始合并”，本次不会写入新结果，也不会覆盖已有的 `优选合集.txt`；未完成来源显示“已停止”。

## 来源维护

支持两种方式：

- **界面维护**：添加、编辑、启停、上移、下移或删除后，自动写入 `URL.txt`。
- **直接编辑 `URL.txt`**：保存文本后回到程序，点击“重新加载”。

自动保存失败时（例如目录无写入权限），配置区显示“自动保存失败，点击重试”。修复后点击提示或按 Ctrl+S 重试。

### URL.txt 格式

每行一个来源，URL 后可用中文或英文逗号添加备注：

```text
https://bestcf.pages.dev/domain/all.txt，精选全量版
https://bestcf.pages.dev/vps789/top100.txt，VPS789 Top100
https://raw.githubusercontent.com/love-ztm/cfip/refs/heads/main/best_ips.txt，GitHub 优选
```

规则：

- 仅支持 `http://` 或 `https://`，地址应直接返回 TXT 文本。
- 备注可省略；空行和普通 `#` 注释行会被忽略。
- 在 URL 前加 `# ` 表示停用该来源，例如 `# https://example.com/list.txt，备用`。
- 同一 URL 只保留首次出现的配置。

## 输出筛选与程序配置

| 选项 | 默认 | 说明 |
|---|---|---|
| 整行精确去重 | 开启 | 完全相同的整行只保留首次出现的一条 |
| IPv4 | 开启 | 只保留行首为 IPv4 的内容 |
| IPv6 | 关闭 | 只保留行首为 IPv6 的内容 |
| GitHub 加速 | 关闭 | GitHub 来源通过 `gh-proxy.org` 下载 |

IPv4 和 IPv6 至少勾选一项。两项都勾选时同时导出；未勾选的 IP 类型会被弃用。

GitHub 加速只影响下载过程，不改变 `URL.txt` 中记录的原始地址。勾选后实际地址示例：

```text
https://gh-proxy.org/https://raw.githubusercontent.com/love-ztm/cfip/refs/heads/main/best_ips.txt
```

非 GitHub 地址不受影响，已代理地址不会重复添加前缀。

上述选项会立即保存到 `程序配置.json`：

```json
{
  "version": 2,
  "deduplicate": true,
  "ipv4": true,
  "ipv6": false,
  "github_accelerate": false
}
```

手工修改该文件后需重新打开程序才会生效；文件损坏时会回退默认值并在状态栏提示。

## 合并规则

- 只下载已启用的来源，结果顺序与列表顺序一致。
- 忽略空白行；未勾选的 IP 类型不导出。
- 域名、普通文本、注释和无法识别的格式也不导出；程序不会进行 DNS 查询。
- 支持 `1.1.1.1:443#备注`、`[2606:4700::1]:443#备注`、裸 IP 等常见格式。
- 输出固定为同目录 `优选合集.txt`，UTF-8 无 BOM、Windows CRLF 换行。
- 单条来源失败会自动重试，不影响其他来源；全部失败或筛选后无内容时不覆盖旧结果。
- 部分来源失败仍可导出成功部分，并会标注“部分成功”。

> 如果来源中大多是“优选域名”而不是 IP，筛选后的行数会明显减少，这是正常的 IP 筛选结果。

## 输入输出示例

输入 `URL.txt`：

```text
https://bestcf.pages.dev/domain/all.txt，精选全量版
https://bestcf.pages.dev/domain/qms/all.txt，QMS 全量版
```

输出 `优选合集.txt`（默认仅 IPv4、已去重）：

```text
162.159.198.1:8443#官方入口 | MASQUE1
43.168.16.112:443#HK [优选高速 47.45ms]
202.144.194.170:443#JP [优选高速 96.75ms]
```

## 界面速查

| 操作 | 说明 |
|---|---|
| 双击列表行 | 编辑来源 |
| 点击“启用”列 | 快速启用 / 停用 |
| 编辑 / 启用停用 / 上移 / 下移 / 删除 | 先选中来源，再点操作 |
| 右键列表行 | 编辑、启停、复制 URL、查看运行详情 |

| 打开输出目录 | 定位 exe 与结果文件 |

## 常见问题

**为什么结果行数明显减少？**  
只保留勾选类型的 IP。域名、HTML、注释、普通文本和未勾选的 IP 类型都会被过滤，完成窗口会显示筛选排除数量。

**IPv4、IPv6 都不选为何不能合并？**  
至少需要选择一种 IP 类型，否则结果必然为空。

**GitHub 加速为什么对某些地址无效？**  
只处理 GitHub 域名（如 `github.com`、`raw.githubusercontent.com`、`*.githubusercontent.com`）。若代理暂时不可用，可取消勾选后重试。

**修改来源后还要保存吗？**  
不需要。新增、编辑、启停、排序、删除都会立即写入 `URL.txt`。

**Windows 提示“已保护你的电脑”**  
程序未做商业代码签名。确认来源后，可点击“更多信息”→“仍要运行”；如受公司策略限制，需要管理员放行。

**提示自动保存失败或无法写入结果**  
将整个工具目录移动到有写权限的位置；修复后点击自动保存提示或按 Ctrl+S。

**修改了文件但界面没变化**  
`URL.txt` 修改后点击“重新加载”；`程序配置.json` 只在程序启动时读取，需重新打开程序。

## 文件说明

```text
CF优选IP合并工具.exe   主程序
URL.txt                来源配置
程序配置.json          输出筛选与 GitHub 加速设置
优选合集.txt           合并结果（运行后生成）
README.md              本说明
```

配置、来源和合并结果均保存在本机。程序只访问 `URL.txt` 中配置的 HTTP/HTTPS 地址，不上传配置或结果，不执行下载内容中的命令或脚本。启用 GitHub 加速时，GitHub 下载请求会经过 `gh-proxy.org`，该服务可获知对应 GitHub 地址。

## 从源码构建

需要 **Python 3.11**（自带标准库 Tkinter），然后执行：

```bat
pip install -r requirements-build.txt
build.bat
```

`build.bat` 会依次完成：运行单元测试 → 生成版本资源 → PyInstaller 打包 → 复制示例配置 → 压缩发布包。产物全部在 `dist\` 目录：

```text
dist\CF优选IP合并工具.exe
dist\CF优选IP合并工具_v<版本>.zip
```

版本号只在 `cf_merger/__init__.py` 的 `__version__` 中维护一处，exe 的文件属性与 zip 文件名都由它自动派生，无需再改打包脚本。

如果 Python 3.11 不在 PATH 中，可先指定解释器再构建：

```bat
set CF_PYTHON=D:\Python311\python.exe
build.bat
```

打包时使用的 `URL.txt` 和 `程序配置.json` 始终取自项目根目录的示例文件，`dist\` 中的旧文件会被覆盖，因此发布包不会包含个人来源清单。
